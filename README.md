# My-First-Practice-Site
This is just a practice site for me to practice what I'm learning in HTML, CSS, and JavaScript. Throughout this description of the site's development, I will use HTML entities so that the elements I describe or mention are visible with their opening and closing tags. Because my website needed to be about something, I decided to create a World Explorer’s Recipe Book, where I share international recipes and communicate my love for travel. I’m not sure if that’s a good idea for a website, but this is just practice, remember.

I began with a basic HTML boilerplate, including my &lt;!DOCTYPE html&gt;, &lt;html lang="en"&gt;&lt;/html&gt;, &lt;head&gt;&lt;/head&gt;, &lt;body&gt;&lt;/body&gt;, and &lt;footer&gt;&lt;/footer&gt; elements. I added a &lt;main&gt;&lt;/main&gt; and a &lt;section&gt;&lt;/section&gt; for the body. I added a title &lt;h1&gt;&lt;/h1&gt;, a subtitle &lt;h2&gt;&lt;/h2&gt;, and a paragraph &lt;p&gt;&lt;/p&gt; introducing myself as Alex and explaining what the site was about. I also added an image &lt;img src="" alt=""&gt; for the beginning (all images have the "alt" attribute for accessibility).

Then, I added another &lt;section&gt;&lt;/section&gt; with proper hierarchy (i.e., &lt;h2&gt;&lt;/h2&gt;, &lt;p&gt;&lt;/p&gt;, etc.) and an unordered list &lt;ul&gt;&lt;/ul&gt; of recipes, with an image &lt;img src="" alt=""&gt; wrapped in a &lt;figure&gt;&lt;/figure&gt; and &lt;figcaption&gt;&lt;/figcaption&gt; element.

Finally, I added a &lt;footer&gt;&lt;/footer&gt; with a &lt;p&gt;&lt;/p&gt; for the copyright.

I then used an &lt;a href="" target="_blank"&gt;&lt;/a&gt; to modify one of the sentences in the introductory paragraph. I wanted to wrap the sentence with the &lt;a>&lt;/a&gt; to link the sentence and, of course, set the href attribute to my destination. In this case, it was just a YouTube channel about a travel vlog. I then wrapped the image, which was already wrapped in a &lt;figure&gt;&lt;/figure&gt;, in an &lt;a href="" target="_blank"&gt;&lt;/a&gt; as well.

Under the figure-wrapped image, I added a clickable hyperlink &lt;a href="" download="">&lt;/a&gt; to an external destination, wrapped around a sentence in a &lt;p&gt;&lt;/p&gt; element. Instead of an external destination, like another webpage, I wanted the hyperlink to download a file and do so immediately. So, I used an &lt;a href="">&lt;/a&gt; set to a direct download link hosted on Google Drive, along with a download attribute that would force the browser to download the linked file directly rather than opening it inside the browser tab. It also pre-sets the saved file's name to "Nelson Family Recipe Cookbook," as the href led to a cookbook. This way, when the user clicks the download text, it directly downloads the cookbook without having to go to another page.

I then added another &lt;section&gt;&lt;/section&gt; as an About page, with a title &lt;h2&gt;&lt;/h2&gt;, paragraph &lt;p&gt;&lt;/p&gt;, and image &lt;img src="" alt=""&gt; of "Alex" (Alex is a fictional character for the purpose of the website), and an unordered list &lt;ul&gt;&lt;/ul&gt; of my favorite cuisines

Then I added another &lt;section&gt;&lt;/section&gt; for a travel vlog. This allowed me to practice using the &lt;iframe width="" height="" title="" src="" allowfullscreen>&lt;/iframe&gt; to embed a video into the website. The &lt;iframe width="" height="" title="" src="" allowfullscreen>&lt;/iframe&gt; had width, height, title, src, and allowfullscreen attributes inside the element.

Then I added a &lt;video>&lt;/video> wrapped in a &lt;figure>&lt;/figure> with attributes like width, src, muted, loop, controls, poster, etc. In the event that it wasn’t displayed on the screen, I added a fallback message inside the &lt;video>&lt;/video>. I then added an &lt;svg>&lt;/svg> to include an illustration of a blue circle divided into four pieces.

I then added another &lt;section>&lt;/section> where I could practice using the &lt;audio>&lt;/audio> element. Instead of including the link in an src attribute as I did in the &lt;video>&lt;/video> element, I decided to do so using an &lt;source src="" type=""> inside the &lt;audio>&lt;/audio> element. My &lt;audio>&lt;/audio> element had attributes like muted, controls, and loop. In the &lt;source src="" type="">, I specified the file type I was using with the type attribute inside the source element.

At this point, I placed a &lt;nav>&lt;/nav> in the &lt;body>&lt;/body> outside the &lt;main>&lt;/main> element, with an unordered list &lt;ul>&lt;/ul> to serve as a kind of navigation bar, or I suppose a list, to help navigate across the different sections I had. I also had to add id attributes to the &lt;section>&lt;/section> elements I already had across my website.

Then I added another &lt;section>&lt;/section> where I could use a &lt;blockquote cite="">&lt;/blockquote> with a cite attribute in my paragraph element, and then, after that, use the &lt;cite>&lt;/cite> element under the &lt;blockquote cite="">&lt;/blockquote> element to show my source. I also used a &lt;span lang="fr">&lt;/span> with an attribute of lang="fr" to highlight a group of text as another language from English.

Then I added another &lt;section>&lt;/section> with a description list &lt;dl>&lt;/dl> and three sets of description terms and definitions, with, of course, the elements corresponding to each. Then I added another section for the use of semantic HTML. Of course, in some sense, most HTML elements are semantic, as opposed to elements like &lt;div>&lt;/div>, which are void of any semantic meaning. Yet, I learned them under "semantic and presentational elements," so that’s how I identify them. This includes &lt;strong>&lt;/strong>, &lt;s>&lt;/s> (for strikethrough), and the superscript element &lt;sup>&lt;/sup>.

Then I used a ruby annotation element &lt;ruby>&lt;/ruby> and a ruby text element &lt;rt>&lt;/rt>, as well as a ruby parenthesis element &lt;rp>&lt;/rp>, inside the containers of the ruby annotation element. The ruby text element contains the actual ruby text that’s going to be above, below, or beside the base text inside the broader ruby element. Then, the ruby parenthesis element supports the ruby text element as a fallback wrapper in case the browser doesn’t recognize the ruby text element. Then, another &lt;span lang="fr">&lt;/span> for good measure. So overall, everything came out like this: &lt;ruby&gt;お好み焼き&lt;rp&gt;(&lt;/rp&gt;&lt;rt&gt;Okonomiyaki&lt;/rt&gt;&lt;rp&gt;)&lt;/rp&gt;&lt;/ruby&gt;.

Continuing with coding, I decided to add a &lt;form>&lt;/form> element for, you know, a form. I first modified the &lt;form>&lt;/form> element with the action and method attributes. Then, I added four &lt;fieldset>&lt;/fieldset> and &lt;legend>&lt;/legend> elements, with the legend being a kind of caption/title for the fieldset, which is simply a group of related inputs in a form.

I debated whether to relate my &lt;label>&lt;/label> and &lt;input> elements implicitly or explicitly and landed on explicit because it’s the way I learned it, and explicit just seems like less trouble in the long run. So, I added an &lt;input>&lt;/input> element and a corresponding &lt;label>&lt;/label> element. The label had a for attribute set to the id of the input element (the input element has an id attribute with the same value as the for attribute in the label element).

To properly create the input element, I made sure it also had the attributes type (because it was a type attribute), name, class, id, required, placeholder, and value. Although, looking back, I’m not sure why I added the value attribute and left it blank. I think it’s because I saw that other inputs, like the &lt;select>&lt;/select> element, had values, so I guessed everything in a form should. Then, I added a &lt;br> element, or line break tag, so that my input elements were separated and not rendered like words in a sentence.

Then I did the same for all the other input elements, changing the attributes when necessary. What I just described was the name input. For the age, I did the same, except the type was number, and it also had a min and max attribute. For the phone input, I used the type tel, and I added a pattern attribute so that I could determine what types of numbers would be recognized by the element according to international phone numbering standards. This includes starting with a plus sign, a country code of 1 to 3 digits, an optional space, a 3-digit area code, etc. Then there was a date input element.

For the second fieldset, I added another text input and a number input, each with their own minlength/maxlength and min/max attributes, respectively. Then, a &lt;select>&lt;/select> element and a &lt;textarea>&lt;/textarea> element. The &lt;select>&lt;/select> element contained &lt;option>&lt;/option> elements with value attributes to include semantic information on what the options represented. One option had a selected and disabled attribute because I wanted it to appear first as a "please select" option that wasn’t really an option. I didn’t want it to be actually part of the options, hence the disabled attribute. Then, a &lt;textarea>&lt;/textarea> element. For the &lt;textarea>&lt;/textarea>, I added rows and cols attributes, as well as a maxlength attribute. Then, I added a series of checkbox input elements in the third fieldset, each with attributes for id, name, class, and value, with the type set to checkbox.

Then, my next fieldset included radio elements, simply yes and no. Then, I added two &lt;button>&lt;/button> elements, one a submit button and the other a reset button. For the reset button, the text has a &lt;strong>&lt;/strong> element, as it was a warning that pressing it would reset all the information on the form.

Then, I added another section that was solely for the purpose of adding a &lt;table>&lt;/table> element. I must confess, this was the hardest out of everything I had done so far. It was taxing remembering everything, and I had to frequently switch between the HTML file and the preview to know how it was rendered across the screen.
